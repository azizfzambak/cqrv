## Method

- Instance: `examples/grover_pred_037.cqr` (n = 8, M = 32), m = 4 (15 controlled iterates), shape tree, both uncomputation modes; the circuit of `countingCircuit` (PHASE2_SPEC §A.3 amendment (4)).
- Machine: 13th Gen Intel(R) Core(TM) i9-13900H; 20 logical CPUs; 2600 MHz; RAM 16108 MB; Microsoft Windows 11 Home Single Language 10.0.26200; `LEAN_NUM_THREADS=4`; run 2026-11-04 23:46:57.
- Toolchain: leanprover/lean4:v4.35.0, Mathlib 56a005855ea1, Physlib 96a6bc5e3c50.
- The block table is `scripts/CertifyTool.lean counting-sample`; every distinct block appears once with its multiplicity (the `2^j` copies of controlled iterate `j` are one literal). The Lean files `bench/counting/Blocks_<mode>.lean` state each block as a literal with its link to the builder (`… = .ok block`, as `emitted_ok`) and its `grade_eq` / `gradeExt_eq` by `decide +kernel`.
- Per declaration: the Stage 18a machinery (`scripts/kernel_forms.py profile`): a copy with `#print axioms <name>` after every declaration, `lean -DElab.async=false -Dprofiler=true -Dprofiler.threshold=T`; the profiler's `… took` lines between two markers belong to the declaration the second marker names; `type checking` is the kernel; lines below the threshold are not printed (`—`). Timeout 900 s; a `lean` process above 8 GB is killed (`mem-kill`). Peak MB is the peak working set of the whole Lean run, not of one declaration.
- The whole circuit's measured grade is the compiled evaluation (`Circuit.grade`), not the kernel's; the composed bound is `⊕` with the multiplicities (Stage 19a, `grade_foldl_append_le` / `grade_replicate_le`; `tDepth` as `tDepth(init) + Σ tCount`).
