- **Front end**: typed term → network: proved (`toNetwork_pred`, `toNetwork_WF`, `toNetwork_succeeds`, Stage 16a, under the decidable scoping hypothesis `tp.scoped`); parser, surface checker and the typed-term printer unverified; every certificate states it since Stage 16b (`net_ok`, `front_end`, kernel-checked; `trust_boundary.front_end` says so).
- **Emitter**: QIR (Adaptive Profile) / OpenQASM 3 text — unverified, translation-validated by re-parse; QIR verified with llvmlite. Stage 17b: the phase gates `p` / `cp` as `p(2*pi*a/2^k)` / `cp(…)` (OpenQASM 3) and as `rz` with a hex-float angle plus the five-gate `decomposeCp` (QIR; `rz(θ) = e^{-iθ/2}·p(θ)`, a global phase per gate, irrelevant to every statement); a `cp` under `ifBit` has no QIR form (diagnostic `unsupported_in_qir`).
- **Solution count M**: decided by the kernel for n ≤ 10 (the default `--count-limit`, Stage 14c; `hM_count`, `Network.countSat_eq_card`; `cqr certify --count-limit k`); a hypothesis (`hM_card`) only for larger n or with `--count-limit 0`.
- **Hardware**: routing, native-gate translation and calibration noise are the backend's; the profile check uses the report's illustrative figures (`profiles/illustrative_sc.json`, not calibration data of any device). δ_hw is vacuous at p̄ = 10⁻² (G·p̄ ≥ 1) — needs error correction or mitigation.
