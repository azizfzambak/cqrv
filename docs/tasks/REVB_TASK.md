## R3 — "emulator_validated" → "emulator_sanity_checked"; the run protocol in the manifest

Today `hw_n2_torino` and `hw_n3_torino` carry the status word `emulator_validated`. The emulator's
noise model is not of the (P-stoch) form, so a passing run is a sanity check of the pipeline, not
evidence for the premise (paper v2, Section 8.4).

1. Rename the status word everywhere it is produced or checked: `CQRV/Hardware/NoiseCertGen.lean`,
   `CQRV/Hardware/CheckGen.lean`, `tests/diff/hw_noisecert_check.py`,
   `tests/diff/hw_physcert_check.py`, `hw/README.md`. Historical documents (`DECISIONS.md`,
   `PHASE2_SPEC.md`, `PHASE2_ROADMAP.md`, `PROJECT_STATUS.md`, `M5_REPORT.md`, task texts) keep the
   old word where they record history; add one sentence to `M5_REPORT.md` (a dated note) saying
   that the word was renamed in revision R3, and why.
2. The `emulator_comparison` block of a manifest records the full protocol: `alpha`, `shots`,
   `seed`, the success count (`p_hat` as count/shots, as now), the one-sided Hoeffding margin
   `sqrt(ln(1/alpha) / (2 shots))` as an exact formula string and as a float, and the comparison
   actually made. Take the seed from the run file (`docs/hw_runs/*.json`); do not re-run.

## R4 — the model premises (P-prep) and (P-ctrl) in every physical and conditional manifest

Paper v2, Table 1 and Section 8.3: the physical statement assumes exact all-|0⟩ preparation
(P-prep) and exact classical control and bookkeeping (P-ctrl), besides the ideal gates and
connectivity of the target. Today the manifests name P-cal, P-stoch, P-ro, P-idle only.

1. Add a `model_premises` object to every physical manifest (`grover_pred_037_torino`) and every
   conditional one (`hw_n2_torino`, `hw_n3_torino`, `mbu_gadget_torino`, the three frontier
   certificates), with one sentence each:
   - `ideal_device`: the target's gates and coupling map, no noise (physical only; for the
     conditional ones the noise premises replace it);
   - `P-prep`: every qubit, data and ancillae, starts in |0⟩ exactly;
   - `P-ctrl`: mid-circuit outcomes are recorded and fed forward exactly; classical bookkeeping is
     exact; the feed-forward latency L is an assumption used for timing only.
2. The `noise.premises` object of the conditional manifests keeps its four entries.
3. Each premise sentence is produced by the Lean generator (one source of truth), and the Python
   checks assert the presence of every premise key.

## R5 — bind the certificate to the library it was checked against

Today `hashes.proof` is SHA3-256 of the certificate `.lean` text with the pinned toolchain, Mathlib
and Physlib revisions (`CQRV/Certify/Certificate.lean`, `proofHash`). The meaning of `Cert.lean`
also depends on the CQRV definitions it imports (`Realizes`, `AncRestore`, `channelDenote`, …).

1. Add `hashes.library`: SHA3-256 over the sorted list of `(path, SHA3-256(content))` for every
   `.lean` file under `CQRV/` and `Apps/`, plus `lakefile.lean`, `lean-toolchain`,
   `lake-manifest.json` (paths with `/`, content as bytes; the exact preimage format is yours;
   document it in the doc-comment and in `docs/certificate.schema.json`). Compute it in Lean (the
   existing SHA3) and mirror it in Python for the checks.
2. **The CI problem this creates**: every library change would change every `certificate.json`
   and break the byte-for-byte re-certification check. Preferred design (record it in DECISIONS
   with the alternative you reject): the re-certification check compares certificate JSON
   **modulo `hashes.library`**, and a separate check (in the same CI step, no new step number)
   reports whether every recorded library hash equals the current tree. It warns by default and is
   blocking with a `--release` flag. At the end of this task the recorded hashes are current.
   If this design does not fit the existing scripts, stop and report before inventing another.
3. The physical and noise manifests already bind the logical `certificate.json` by hash, so they
   inherit the binding; do not add a second library hash to them.
4. The `hardware_perturbation` block of `certificate.json` (the old formula δ_hw ≤ δ + G·p̄ with
   p̄ a profile parameter) is not a theorem. It was superseded by the conditional certificates.
   Keep its counts, but add `"status": "illustrative estimate from the profile, not a theorem;
   see hw noisecert for the proved conditional bound"`, so that no reader takes it for a
   guarantee.
