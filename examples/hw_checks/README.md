# Per-instance hardware checks (Stage 26c1b; the frontier files, Stage 27c)

PHASE2_SPEC §C.3; report §5.3, §9.1.1. One directory per committed artifact of `hw/artifacts/`,
each holding `Check.lean`, **generated by `cqr hw check --artifact <dir> --target <target.json>`
(do not edit)** and checked by the Lean kernel with `lake env lean` — these files are not part of
`lake build`, as the certificates are not.

Each file carries, as Lean literals, the artifact's logical circuit `C` (`logical.json`), its
witness `W` (`witness.json`, compacted to the used qubits), its physical circuit `G`
(`physical.json`, compacted), the compact → device list `dev` and the target's coupling map
`edges`, and proves by the kernel (`rfl`, `decide +kernel`, never `native_decide`):

| theorem | statement |
|---|---|
| `recon` | `applyWitnessQ b C W N = .ok G` — the linear dependency-queue check reconstructs `G` from `C` and `W` exactly |
| `phys_wf`, `phys_nBits`, `c_wf` | the physical circuit is well formed with `C`'s bit count; `C` is well formed |
| `edges_ok` | every two-qubit gate of `G` lies on a coupling edge of the target, in either orientation |
| `init_layout`, `init_eq` | the initial layout is a layout, and is `layOf` of its permutation `σ₀ = layPerm …` |
| `phys_channel` | `applyWitness_sound` at the instance (through `applyWitnessQ_ok`): the physical circuit on the embedded input laid out by `σ₀` is the embedded logical output laid out by `σf = finalPerm …`, which extends `W.final` |
| `phys_zero` | from the all-|0⟩ physical state, the output is `σf`'s embedding of the logical output from |0⟩ (`embed_zero`) |
| `tamper_recon`, `tamper_edges` | `G` with one gate changed is not the reconstruction; a two-qubit gate off the edges is refused |

The two `#print axioms` lines (`phys_channel`, `phys_zero`) name exactly `[propext,
Classical.choice, Quot.sound]` in every file. The header records the SHA3-256 digests of the three
JSON files and the target's snapshot hash; `tests/diff/hw_checks_check.py` confirms them against
the artifact and regenerates the file byte for byte, and `scripts/check_hw_checks.sh` (the CI step
"Hardware checks") then runs every file through the kernel.

**The link from `C` to the instance is the hash** of `logical.json`, which is the manifest's
`logical_circuit` and also the `circuitHash` of the literal `C` (the generator checks both). That
link is untrusted; the physical certificates (`examples/certs/*_torino`, `*_washington`) add the
trusted link `emitted_eq` for the certified instances. Nothing here is "verified on hardware": the
physical circuit is validated against the logical one on the target's coupling map; the emulator
runs of `docs/hw_runs/` are reported, not certified.
