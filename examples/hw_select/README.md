# Selection by the physical grade (Stage 26c2b)

PHASE2_SPEC §C.3; report §3.1.3, §5.3. One directory per request–target pair, each holding
`Select.lean`, **generated by `cqr hw select --request <name> --target <target.json> --prefer bound`
(do not edit)** and checked by the Lean kernel with `lake env lean` (not part of `lake build`).

The candidates are the request's committed artifacts on the target (`hw/artifacts/<request>_*__<target>/`),
each with its uncomputation mode and its `PhysGrade` at the stated feed-forward latency L (an
assumption; 0 ns in the committed files). A file holds every candidate's physical circuit and its
rate and duration tables as literals, each `PhysGrade` decided by the kernel (`grade_i`), the choice
`selectPhys ff budget pref cands = some c` (or `none`) decided by the kernel (`choice`), and the
`selectPhys_spec` instance (`choice_spec`: the choice is admissible — mbu needs the target's
feed-forward, the budget holds — and minimal for the component among the admissible candidates;
`none` iff no candidate is admissible). The `#print axioms` line names the standard three axioms.

Each candidate's `physical.json` SHA3-256 in the file links it to `examples/hw_checks/<artifact>/Check.lean`,
where its reconstruction, coupling edges and channel theorem are checked (CI step "Hardware
checks"); a `Select.lean` does not repeat them. `tests/diff/hw_select_check.py` confirms the links
and regenerates the files byte for byte; `scripts/check_physcert.sh` (CI step "Physical
certificate", pass mark 25) runs them through the kernel.

The `noise` column (Stage 27b, `cqr hw select --prefer noise`, `selectNoise`) is the conditional
noise bound `δ + Σ p_g + Σ r_j` of `CQRV/Hardware/Noise.lean` (the Pauli reading with the clamp;
none of these candidates clamps); the other FakeTorino candidates: grover_pred_037 tree coherent
2.4046, tree mbu 2.8990; simple_alu_x0_1 tree coherent 4.3220, tree mbu 4.5368. Every noise bound here
is vacuous (≥ 1), so `--prefer noise --budget 1` returns `none` for both requests on FakeTorino — the
honest answer. The `noise` preference writes no `Select.lean`; the committed files are the grade
preferences'. Conditional on the premises (P-stoch), (P-ro), (P-idle), (P-cal); not a fact about a device.

The other candidates on FakeTorino — grover_pred_037: tree coherent 375 two-qubit / 20116 ns /
bound 1.9141, tree mbu 315 / 33740 → 43740 ns / 2.4495; simple_alu_x0_1: tree coherent 536 / 24948 ns
/ 3.5025, tree mbu 470 / 40460 → 46092 ns / 3.8083. On FakeWashington (no feed-forward) only the
coherent candidate is admissible (§A.9 (5)); the mbu artifacts of these requests exist only on
FakeTorino.

The committed `Select.lean` files are for `--prefer bound`. The committed physical certificate
(`examples/certs/grover_pred_037_torino`, tree mbu) was generated with an explicit mode; selection
under the bound chooses fewlog mbu instead, which is reported here, not forced.

**The budget test.** On FakeTorino, `--prefer bound --budget 1` returns `none` for both requests:
every physical bound there is ≥ 1 (the error-1.0 edges of the fake's calibration, 25a), so no
candidate is admissible — the honest answer, not an error (`tests/diff/hw_select_check.py`).

Nothing here is "verified on hardware": the bound is a sum of calibrated rates, reported, not
certified (Stage 27 is the noise theorem); the depth is a timing model at an assumed latency.
