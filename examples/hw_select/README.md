# Selection by the physical grade (Stage 26c2b)

PHASE2_SPEC §C.3; report §3.1.3, §5.3. One directory per request–target pair, each holding
`Select.lean`, **generated by `cqr hw select --request <name> --target <target.json> --prefer bound`
(do not edit)** and checked by the Lean kernel with `lake env lean` (not part of `lake build`).

The candidates are the request's committed artifacts on the target (`hw/artifacts/<request>_*__<target>/`),
each with its uncomputation mode and its `PhysGrade` at the stated feed-forward latency L (an
assumption; 0 ns in the committed files). A file holds every candidate's physical circuit and its
rate and duration tables as literals, each `PhysGrade` decided by the kernel (`grade_i`), the choice
`selectPhys ff budget pref cands = some c` (or `none`) decided by the kernel (`choice`), and the
`selectPhys_spec` instance (`choice_spec`: the choice is admissible — mbu needs the target's
feed-forward, the budget holds — and minimal for the component among the admissible candidates;
`none` iff no candidate is admissible). The `#print axioms` line names the standard three axioms.

Each candidate's `physical.json` SHA3-256 in the file links it to `examples/hw_checks/<artifact>/Check.lean`,
where its reconstruction, coupling edges and channel theorem are checked (CI step "Hardware
checks"); a `Select.lean` does not repeat them. `tests/diff/hw_select_check.py` confirms the links
and regenerates the files byte for byte; `scripts/check_physcert.sh` (CI step "Physical
certificate", pass mark 25) runs them through the kernel.

certified (Stage 27 is the noise theorem); the depth is a timing model at an assumed latency.
